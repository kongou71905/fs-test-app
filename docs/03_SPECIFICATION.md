# 麻雀成績管理アプリ 仕様書

## 1. 要件定義

### 1.1 プロジェクト概要
* **目的**: これまで紙と手計算で行っていた麻雀の成績管理をWebアプリ化し、入力・計算の省力化およびデータの恒久的な蓄積・分析を可能にする。
* **対象端末・環境**: iPad mini 6（Safari）、オンライン環境必須。
* **利用者**: 開発者および限定されたメンバー数名。

### 1.2 システム構成（インフラ・デプロイ）
すべて無料で運用可能な以下の構成を採用する。
* **フロントエンド**: HTML / CSS (Tailwind CSS) / Vanilla JavaScript
  * ホスティング: **GitHub Pages**
* **バックエンド / データベース**: **Google スプレッドシート** ＋ **Google Apps Script (GAS)**
  * GASをWebアプリとして公開し、JSON形式のAPI経由でデータの読み書きを行う。
  * スプレッドシートに直接データを蓄積することで、端末変更時のデータ消失を防ぎ、シート上での自由なデータ集計・分析を可能にする。

### 1.3 機能要件一覧
1. **対局者管理機能**
   * 対局者の新規登録、名前編集、削除（論理削除または過去データへの影響がない形式）。
2. **対局設定機能**
   * 対局日の設定（デフォルトは当日日付）。
   * 参加対局者の選択（4名以上選択可能）。
3. **半荘スコア入力・計算・修正機能**
   * 半荘ごとに参加4名の席順（東南西北）、素点、飛び、焼き鳥を入力し、自動で最終ポイントを算出する。
   * 入力済みの半荘データは、いつでも再編集・削除ができる。
   * 任意の半荘数まで繰り返し追加できる（半荘数が多い場合は縦スクロール表示）。
   * 参加者が5名以上の場合は全員分の列を表示する（横スクロール表示）。
4. **チップ管理・集計・確定機能**
   * 1日の終了時に、初期20枚からの増減枚数を入力してポイント換算する。
   * 現在の「成績（半荘合計＋チップ）」をリアルタイムで常時表示する。
   * 「集計」ボタン押下時、各対局者の成績に係数50を乗算した精算用数値をポップアップ表示する。
   * 「終了」ボタン押下時、1日の成績および全半荘の詳細データをGoogleスプレッドシートへ送信・保存する。
5. **過去データ閲覧機能**
   * 保存された過去の成績を年単位（2026年、2025年…）または「全期間」で絞り込み一覧表示する。
   * 日別成績の行を選択することで、その日の「半荘ごとの成績詳細」を確認できる。

## 2. 外部設計（画面・UI/UX・計算仕様）

### 2.1 画面遷移図
```text
[トップ画面 (index.html)]
 ├── [管理] ──> [対局者管理画面 (management.html)]
 ├── [データ] ─> [過去データ画面 (data.html)] ──(行タップ)──> [半荘詳細モーダル]
 └── [入力] ──> [日付対局者設定画面 (input_setup.html)]
                  └──(OK)──> [成績表示画面 (score.html)]
                               ├── [入力] ──> [半荘スコア入力モーダル]
                               ├── (行タップ) ─> [半荘スコア編集・削除モーダル]
                               ├── [チップ] ─> [チップ増減入力モーダル]
                               └── [集計] ──> [精算集計ポップアップ (×50)]
```

### 2.2 麻雀ルール・計算ロジック仕様
1. **基本設定**
   * **持ち点・返し点**: 25,000点持ち / 30,000点返し
   * **オカ（トップ賞）**: +20ポイント（1位に自動加算）
   * **ウマ（順位点）**: 10-20（1位: +20、2位: +10、3位: -10、4位: -20）
2. **順位決定ルール**
   * 素点の多い順に1位〜4位を決定する。
   * **同点時の処理**: 選択された席順（**東 ＞ 南 ＞ 西 ＞ 北**）に従い、東家に近い方を上位とする。
3. **端数計算とゼロサム調整**
   * 2位・3位・4位の素点差分 `(素点 - 30000) / 1000` に対し、**100点単位で切り上げ**（0方向への切り上げ `Math.ceil`）を行い整数化する。
   * 2位・3位・4位の最終ポイント = `切り上げ後差分 + ウマ + 飛び + 焼き鳥`
   * **1位の最終ポイント** = `-(2位の最終ポイント + 3位の最終ポイント + 4位の最終ポイント)` とし、半荘ごとの4人合計が必ず `0` になるよう調整する。
4. **特殊要素の計算**
   * **飛び（トビ）**:
     * 飛ばされた人（複数選択可）: `-5`
     * 飛ばした人: `+5 × 飛ばした人数`
   * **焼き鳥（鳥）**:
     * 焼き鳥対象者が合計 `-15` を支払い、焼き鳥ではないプレイヤーが均等に受け取る（割り切れない場合は切り捨て）。
     * 対象1人（受取3人）: 対象者 `-15` / 受取側 各 `+5`
     * 対象2人（受取2人）: 対象者 各 `-7` / 受取側 各 `+7`
     * 対象3人（受取1人）: 対象者 各 `-5` / 受取側 `+15`
     * 対象0人または4人: 増減 `0`
5. **チップ・集計計算**
   * **チップ**: 初期20枚持ち。増減枚数（全員の合計が0）を入力し、`増減枚数 × 2` をポイントとして加算する。
   * **集計ポップアップ**: `各対局者の成績 × 50` を表示する。

### 2.3 画面別UI仕様（iPad mini 6 最適化）
* **成績表示画面 (`score.html`)**:
  * 参加者4名の場合は均等4列、5名以上の場合は人数分の列を表示し、横スクロール可能とする（左端の半荘番号列は固定）。
  * 半荘数が多い場合はテーブルボディを縦スクロール可能とし、ヘッダー（対局者名）およびフッター（チップ行・成績行）を常時画面内に固定表示する。
  * 抜け番のプレイヤーのセルは空欄（または「ー」）とし、成績行には参加した半荘分のみを合算する。
* **過去データ画面 (`data.html`)**:
  * 左端の日付列を固定し、登録されている全対局者の列を均等幅で表示する。
  * 対局者名が5文字以上の場合は、4文字ごとに改行して折り返し表示する。
  * 「期間」ボタン押下時、データが存在する年（2026年、2025年…）および「全期間」を選択できるモーダルを表示する。

## 3. 内部設計（データ構造・API設計）

### 3.1 Google スプレッドシート データベース設計
1つのスプレッドシート内に以下の3つのシート（テーブル）を作成する。

#### ① `Players` シート（対局者マスタ）

| カラム名 | 型 | 説明 |
| :--- | :--- | :--- |
| `player_id` | String | 一意のID（例: `P001`） |
| `name` | String | 対局者名 |
| `is_active` | Boolean | 有効フラグ（削除時は `FALSE` にし、過去データの表示名は維持する） |
| `created_at` | DateTime | 登録日時 |

#### ② `DailyRecords` シート（日別最終成績・分析用）

| カラム名 | 型 | 説明 |
| :--- | :--- | :--- |
| `session_id` | String | 対局日セッションID（UUID等） |
| `date` | Date | 対局日（`YYYY/MM/DD`） |
| `player_id` | String | 対局者ID |
| `player_name` | String | 対局者名（スナップショット） |
| `game_count` | Number | 当日の参加半荘数 |
| `chip_diff` | Number | チップ増減枚数 |
| `chip_point` | Number | チップポイント（`chip_diff * 2`） |
| `total_point` | Number | 当日最終成績（半荘合計 ＋ チップポイント） |

#### ③ `GameDetails` シート（半荘別詳細ログ）

| カラム名 | 型 | 説明 |
| :--- | :--- | :--- |
| `session_id` | String | `DailyRecords` と紐づくセッションID |
| `date` | Date | 対局日（`YYYY/MM/DD`） |
| `game_number` | Number | 半荘番号（1, 2, 3...） |
| `player_id` | String | 対局者ID |
| `wind` | String | 席順（`東`, `南`, `西`, `北`） |
| `raw_score` | Number | 素点（例: `35400`） |
| `rank` | Number | 順位（1〜4） |
| `is_tobi` | Boolean | 飛ばされたフラグ |
| `tobi_count` | Number | 飛ばした人数 |
| `is_yakitori` | Boolean | 焼き鳥フラグ |
| `final_point` | Number | 半荘最終ポイント |

### 3.2 GAS Web API インターフェース設計
* **エンドポイント**: GAS Webアプリの公開URL（`https://google.com`）
* **認証方式**: リクエスト時にフロントエンドで保持（または初回入力）する簡易パスコードを送信し、GAS側で一致検証を行う。
* **主なAPIアクション (`action` パラメータ)**:
  * `GET ?action=getInitialData`: `Players`、`DailyRecords`、`GameDetails` の一覧を一括取得する。
  * `POST { action: "savePlayers", players: [...] }`: 対局者マスタの追加・更新・論理削除を行う。
  * `POST { action: "saveSession", daily: [...], details: [...] }`: 1日の対局終了時に、日別成績と全半荘詳細をスプレッドシートへ一括追記する。

### 3.3 フロントエンド状態管理（途中保存・リカバリー）
* 対局中（`score.html` 操作中）の未確定データは、誤ってSafariのタブを閉じたりリロードしたりしても消えないよう、一時的にブラウザの `localStorage` に自動バックアップする。
* 「終了」ボタン押下後、GAS APIへの保存が正常完了したタイミングで一時データをクリアする。
